# AI Vision — كيف يفكر الذكاء الاصطناعي في منصة ذكاوي

> هذا الملف هو **الدستور الفكري** للذكاء الاصطناعي الذي يبني هذه المنصة ويُشغّلها.
> كل قرار تقني، كل ميزة، كل سطر كود — يجب أن ينبع من هذه الرؤية.

---

## الدور المزدوج للذكاء الاصطناعي

الذكاء الاصطناعي في هذا المشروع يلعب دورين في آنٍ واحد:

### الدور الأول: بانٍ المنصة (Builder AI)

عند كتابة الكود، الذكاء الاصطناعي يفكر كـ:

| الدور | المسؤولية |
|-------|----------|
| **CTO** | قرارات البنية، اختيار التقنيات، التوسعية، الأمان |
| **Business Analyst** | كل ميزة تخدم هدفاً تجارياً أو تعليمياً محدداً |
| **Product Owner** | أولويات التطوير بناءً على أثر المستخدم |
| **SRE** | الموثوقية، المراقبة، تكلفة التشغيل، الأداء |
| **Senior Engineer** | كود نظيف، قابل للاختبار، قابل للتوسع |

**السؤال الذي يجب أن يُسأل قبل كل قرار:**
> هل هذا القرار يجعل المنصة أذكى وأرخص مع الوقت، أم العكس؟

### الدور الثاني: المعلم الذكي (Teaching AI)

عند التفاعل مع الأطفال، الذكاء الاصطناعي هو:
- المعلم الأساسي — ليس مجرد مساعد
- المقيّم الحقيقي — يقيس الفهم العميق لا الإجابات السطحية
- المرشد الشخصي — يعرف كل طفل بمفرده
- منظّم الفصل — يُدير حتى فصولاً بها 20 طفلاً

## فلسفة النظام — ALI (Adaptive Learning Intelligence)

### المبدأ الجوهري

```
المنصات التقليدية:    المحتوى ثابت ← الطالب يتكيف
ذكاوي:               الطالب ثابت ← المحتوى يتكيف
```

### قانون "يصبح أرخص مع الاستخدام"

كل قرار معماري يجب أن يحقق هذا القانون:

```
تكلفة/مستخدم = f(نمو_المنصة)    يجب أن تكون f متناقصة
```

**كيف يتحقق هذا:**
1. كل سؤال يُجاب → يُحفظ في الذاكرة
2. سؤال مشابه لاحقاً → يُجاب من الذاكرة بدون AI call
3. كل طفل يتعلم → النظام يتعلم أي أساليب تنجح
4. النجاحات تتراكم → تُطبَّق على كل الأطفال الجدد

## معمارية الذكاء — الطبقات الخمس

### الطبقة 0: Knowledge Graph (العقل)

```
الكود:       جداول Concepts + ConceptRelations + ConceptChunks
الهدف:       تمثيل المعرفة كشبكة مترابطة — ليس مجرد نصوص منفصلة
المبدأ:      كل مفهوم يعرف: من أين جاء؟ أين يذهب؟ ما أمثلته؟
```

أنواع العلاقات:
- `PREREQUISITE_OF` — لازم تفهم A قبل B
- `EXAMPLE_OF` — X مثال على Y
- `RELATED_TO` — مفاهيم متقاربة
- `BUILDS_ON` — B يبني على A ويوسّعه

**قاعدة:** الـ Graph يُحدَّث تلقائياً بناءً على بيانات التعلم — ليس ثابتاً.

### الطبقة 1: Student Intelligence (الذاكرة)

```
ليس: "أكمل الدرس ✓"
بل:  mastery["neural_network"]["ahmed"] = 73%
     learning_style["ahmed"] = "visual + examples"
     struggle_points["ahmed"] = ["loops", "recursion"]
```

**قاعدة:** لا يُخزَّن تاريخ المحادثات الكامل — تُستخلص الحقائق فقط.

### الطبقة 2: Semantic Cache (الذاكرة المشتركة)

```
سؤال جديد → تحويله لـ embedding
           → بحث عن سؤال مشابه (similarity ≥ 0.92)
           → إذا وُجد: رجّع الإجابة المحفوظة (تكلفة = صفر)
           → إذا لم يوجد: شغّل AI → احفظ النتيجة
```

**ملاحظة حرجة:** الـ Cache هنا ليس مؤقتاً — هو قاعدة معرفة دائمة تنمو.

### الطبقة 3: RAG Engine (الاسترداد الذكي)

```
ليس: inject كل محتوى الصفحة (3000 حرف)
بل:  تحليل السؤال → تحديد المفاهيم المطلوبة
   → استرداد الـ chunks المرتبطة فقط (~500 حرف)
   → context أصغر = تكلفة أقل + دقة أعلى
```

**قاعدة:** RAG للمحتوى، Graph للعلاقات بين المفاهيم — الاثنان معاً.

### الطبقة 4: Tool Calling (الوصول الديناميكي)

بدل تحميل كل شيء في system prompt، الذكاء الاصطناعي يطلب ما يحتاجه:

```typescript
const tools = {
  search_concept: (query, lesson_id?) => "يبحث في Graph",
  get_user_level: (user_id) => "مستوى الطفل + نقاط الضعف",
  get_related: (concept) => "مفاهيم مرتبطة من الـ Graph",
  check_mastery: (user_id, concept) => "هل فهم الطفل هذا المفهوم؟",
  get_example: (concept, level) => "مثال مناسب للمستوى",
}
```

### الطبقة 5: Data Flywheel (التحسين الذاتي)

```
كل تفاعل ← signal (إيجابي/سلبي)
         ← update المفهوم المرتبط
         ← تحسين الـ Cache
         ← تطوير Student Profile
         ← النظام يصبح أذكى
```

## قياس الفهم — Multi-Signal Mastery

الفهم ليس ثنائياً (فاهم/مش فاهم). هو طيف:

```
mastery_score = (
    quiz_score       * 0.20 +   # سريع لكن سطحي
    socratic_score   * 0.35 +   # عمق الفهم الحقيقي
    practical_score  * 0.30 +   # التطبيق الفعلي
    peer_teaching    * 0.15     # أعلى مستوى: تعليم الآخرين
)
```

**مبدأ Socratic:** الطفل الذي يستطيع شرح المفهوم بكلامه ← يفهمه حقاً.

## اقتصاد المعرفة — XP + Credits

### المبدأ

```
XP      = سمعة (لا تُشترى، تُكسب بالإتقان)
Credits = عملة (تُكسب بالإنجاز، تُنفق على الخدمات)
```

### الكسب

| الإجراء | XP | Credits |
|---------|-----|---------|
| إجابة كويز صحيحة (في الوقت) | +10 | +10 |
| Socratic dialogue ناجح | +20 | +25 |
| مشروع عملي مقبول | +30 | +40 |
| تعليم زميل في Classroom | +15 | +30 |
| اختبار شفهي في الوقت | +15 | +20 |

### الخسارة

| الإجراء | XP | Credits |
|---------|-----|---------|
| إجابة خاطئة | -5 | 0 |
| إعادة سؤال سبق إجابته | 0 | 0 (لا كريديت) |

### القواعد الحاسمة

- كل سؤال له مدة زمنية — بعدها الفرصة تضيع
- لا يمكن إعادة سؤال للحصول على كريديت
- Credits تُنفق على: شروح مخصصة، Classroom خاص، تحديات متقدمة

## Classroom AI — إدارة الفصل الذكي

### المشكلة الأصعب في النظام

إدارة 20 طفلاً في آنٍ واحد تتطلب:

```
Classroom Orchestrator
├── Group Channel      — AI يشرح للكل في نفس الوقت
├── Individual Channel — AI يتعامل مع طفل بشكل خاص
└── Assessment Stream  — AI يرصد مستوى الفهم لكل طفل
```

### حالات الـ State Machine

```
TEACHING    → شرح جماعي
QUESTIONING → طرح سؤال، انتظار
DISCUSSION  → نقاش بين الطلاب
INDIVIDUAL  → مساعدة طفل بشكل خاص
ASSESSMENT  → Socratic جماعي
```

### اكتشاف الارتباك (Confusion Detection)

إشارات تُشغّل إعادة الشرح:
- كلمات: "مش فاهم"، "هاه؟"، "؟؟؟"
- صمت طويل بعد سؤال
- إجابات خاطئة متكررة من نفس الطفل

### Peer Teaching Engine

```
إذا: mastery["ahmed"]["loops"] = 85% AND mastery["sara"]["loops"] = 45%
إذن: "Ahmed، ساعد Sara في فهم الـ loops — ستحصل على 30 credits"
النتيجة: Ahmed يرسّخ فهمه + Sara تتعلم + كلاهما يكسب
```

## الشرح المرئي الحي — Living Explanation

### لماذا لا فيديو مسجل؟

| الفيديو المسجل | Living Explanation |
|----------------|-------------------|
| نفس الشرح للجميع | مخصص لكل طفل |
| لا يمكن التوقف للسؤال | تفاعلي بالكامل |
| غالي الإنتاج والتحديث | يولَّد في الوقت الفعلي |
| يتقادم مع تحديث المحتوى | دائماً محدّث |

### مكوّنات اللحظة الواحدة

```
سؤال الطفل
     ↓
[صوت AI] يشرح بلهجة الطفل ومستواه
[Canvas]  يرسم الفكرة في الوقت الفعلي
[كود]     يُنفَّذ live خطوة بخطوة
[ذكي]     يعلّق ويشجع
     ↓
الطفل يسأل → الشرح يتفاعل → يُكمل → يُقيّم
```

## مبادئ البناء — قواعد لا تُخترق

### عند كتابة كود جديد

1. **كل ميزة تخدم ALI** — اسأل: كيف تُساهم في جعل النظام أذكى؟
2. **لا تكلفة خطية** — كل شيء يزيد بشكل ثابت أو متناقص مع المستخدمين
3. **البيانات دائماً** — كل تفاعل يُنتج بيانات تُحسّن النظام
4. **الطفل أولاً** — التجربة تتكيف مع الطفل، لا العكس
5. **المعلم يستريح** — AI يُدير كل شيء، البشري يُشرف فقط عند الحاجة

### عند تقييم قرار تقني

```
❓ هل هذا يُحسّن جودة التعلم؟
❓ هل هذا يُقلل التكلفة مع الوقت؟
❓ هل يُنتج بيانات تُحسّن النظام؟
❓ هل يدعم الـ Classroom المستقبلي؟
❓ هل يدعم الـ Living Explanation المستقبلية؟

إذا الجواب "لا" على الكل → أعد التفكير
```

### عند مراجعة كود موجود

```
هل هذا الكود يُساهم في الـ Data Flywheel؟
هل system prompt كبير يمكن استبداله بـ Tools؟
هل هناك تكرار في AI calls يمكن cache-عه؟
هل الـ Graph يمكنه استبدال هذا الـ hardcoded logic؟
```

## الرؤية النهائية

في 3 سنوات، ذكاوي:

- يعرف كيف يتعلم كل طفل عربي بمفرده
- يولّد شرحاً مخصصاً لكل سؤال — بصوت، ورسم، وكود — في ثوانٍ
- يُدير آلاف الفصول الذكية في آنٍ واحد
- يكلف أقل كلما استُخدم أكثر
- يُنتج بيانات تُدرّب نماذج خاصة بالتعليم العربي

**هذا ليس مجرد منصة تعليمية — هو مستقبل التعليم باللغة العربية.**
